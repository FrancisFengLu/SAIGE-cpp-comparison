### 本代码库 tau 的运行间噪声带 (重要方法论结论)

**同一个 -O2 二进制、同一 config (trace_seed=200)、8 线程, 3 次运行 tau 各不相同**:

| 运行 | tau[1] | VR (null) |
|---|---|---|
| opt_base (基线) | 0.422442 | 0.904348 |
| opt_o2_r2 | 0.420391 | 0.904121 |
| opt_o2_r3 | 0.404980 | 0.901122 |

噪声带: tau ∈ **[0.405, 0.422]**, 带宽 ~4.3%。来源: TBB `parallelReduce` 的浮点求和顺序
在多线程下不确定 (fp 加法不结合), trace 估计与 PCG 收敛路径随之漂移。
**推论: 多线程下 1e-6 级验收线不可达**; 多线程验收标准 = tau 落在噪声带 (或 2 倍带宽) 内。
严格逐位验收必须用 nthreads=1 (TBB 归约顺序确定)。

# Phase 1: AVX2 融合解码内核 (2026-08-28)

设计: AVX2_KERNEL_PLAN.md (vpshufb 4 相位解码 + 交错序摊销 + 秩一分解两趟)。
实现文件:
- tools/avx2_kernel/avx2_kernel.hpp — 内核 (header-only): permute_fwd / pass1_sum_gx /
  pass2_axpy / unpermute_sub / decode_row_perm
- SAIGE_step1_fast.cpp — genoClass::packed_row_ptr/packed_rows_contiguous (两种存储模式都给
  连续行指针, numMarkersofEachArray==1 保证 legacy 路径也逐 marker 连续);
  CorssProd 加 m_avx2_mode/m_xperm/m_Sx/m_Coffset; parallelCrossProd 里做 Sx(fp64)+permute,
  reduce 后 unpermute−Coffset。parallelCrossProd_full/LOCO 仍走标量 (mode 0)。
- Makefile: 只给 SAIGE_step1_fast.o 加 `-mavx2 -mfma -ffp-contract=off`, 其余 .o 与
  Phase-0 基线完全一致 (conda env 导出的 CXXFLAGS=-march=nocona -O2 覆盖了 Makefile 的
  ?=, 基线对象里 ymm=0 —— 即 Phase-0 实际是 nocona -O2 编的, OPT_LOG 上一节记录的
  -O3/-march=native 并没有生效到当前 .o)。
- 开关: SAIGE_NO_AVX2=1 回退标量; SAIGE_AVX2_PASS1_ONLY=1 只用趟1 (验证档);
  SAIGE_AVX2_VERIFY=1 每次 ψv 双跑对比; SAIGE_TIME_PSIV=1 打印 ψv 累计耗时。

## 编译陷阱 (记录)

1. conda activate 导出 CXXFLAGS → Makefile `?=` 失效 → 必须用 target-specific 追加。
2. `-mfma` 下 GCC 默认 fp-contract=fast, 整个 TU 的标量 a*b+c 被收缩成 FMA, tau 从
   0.408076 漂到 0.408075。加 `-ffp-contract=off` 后标量路径逐位复原 (内核用显式
   _mm256_fmadd intrinsics, 不受此 flag 影响)。
